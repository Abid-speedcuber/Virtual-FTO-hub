# Keyboard and recording overlay

Enable **Show keyboard** in Settings. The overlay uses physical key positions rather than the characters generated by the operating system. Keycaps display their current actions: for example, the F position can display `U′`, `8Fw`, or `8F`. Keys without an action stay empty. ANSI and ISO layouts include the function row, navigation cluster, inverted-T arrows, staggered letter rows, and correctly sized modifiers/Space/Enter. The optional number pad has tall Enter/Add and a double-width zero.

The keyboard lives beside the timer in the space to the right of the square puzzle, without covering it. When that space is too narrow, the panel moves below the square. Its default maximum width is 900px, with a 220–1200px width setting; its actual size fits the available panel. Peak and turn count are available in the TPS tooltip.

The overlay is interactive as well: pointer presses on keycaps use the same input engine as physical keys. Press highlights follow key-down and key-up directly, without a minimum duration, afterglow, fade, or polling delay. A 10ms press is not intentionally stretched; visible timing is still limited by browser rendering and display refresh. Pending suffix selection and its faint affected-key glow are separate indicators, not held-key highlights. Move labels are frozen for that press, so consuming a suffix does not relabel a lit key as a different turn.

## Default map

| Input | Action |
| --- | --- |
| U, R, F, J, L, B, K, D | U, R, F, BR, L, B, BL, D |
| 1–9 | Select width 1–9 |
| 0 | Select width 10 |
| Shift+1–9 | Select width 11–19 |
| Shift+0 | Select width 20 |
| Shift+8 / `*`, or NumpadMultiply | Select width 18 |
| Hold Shift | Single slice at the pending depth; depth two if none |
| Hold Ctrl | Wide turn at the pending width; two layers if none |
| Hold Alt | Reverse the resolved move |
| M | Cycle through keyboard modes |
| Ctrl/Meta+Z or Backspace | Undo a player move (stops at the generated scramble) |
| Ctrl/Meta+Shift+Z or Ctrl+Y | Redo |
| Home | Home view |
| Escape | Clear pending depth/sequence and cancel queued turns |

Defaults can all be edited or removed. Numbers no longer turn individual faces. Mouse and face-button modifiers retain their original Shift-wide/Ctrl-slice/Ctrl+Shift-ultra behavior.

A suffix applies to the next accepted turn only. Unbound keys, held action keys, and mode switches leave it waiting. Its key stays selected after release, and affected move keys have a faint glow until the turn consumes it. Press the same suffix again or Escape to cancel early. Another suffix replaces the selection.

`8`, then `F` produces one `8Fw`; a second F is a regular outer turn. `8`, then held Shift with `F` produces `8F`: one slice at depth eight. `Shift+8`, release Shift, then `F` produces `18Fw`. Keeping Shift down instead produces slice eighteen. The shifted suffix key retains its selected `18w` label after Shift is released, until used or cancelled.

Suffix keys that exceed the current puzzle size are blank and inactive, including custom and shifted bindings. For example, 8w is hidden on a 7×7. Pressing one does not replace a valid selection. Explicit move bindings whose resolved range will not fit are rejected rather than clamped. Old sticky-suffix preferences are migrated to one-shot behavior.

## Editing bindings

Open **Settings → Keyboard & bindings**. Select **Mode to edit**, then choose an existing binding or New binding. Enter a trigger, or use Record chord and press/release the chord together. Choose an action and save. Clicking an existing trigger edits that row; adding a duplicate is rejected rather than overwriting it.

- `F`: a single physical key.
- `A+F`: hold A and press F. Chord order does not affect conflict detection.
- `Ctrl+Alt+F`: a modifier chord.
- `A F`: tap A, then F within the sequence timeout.
- `KeyF`, `ShiftLeft`, `ShiftRight`, `ArrowUp`, `Numpad8`, `IntlBackslash`: explicit physical codes.
- `Ctrl`, `Control`, `Shift`, `Alt`, and `Meta` match either side. Side-specific bindings are supported; overlapping generic/side-specific duplicates are rejected.

The timeout is configurable. An immediate action cannot also be the start of a longer tap sequence: it would execute before the sequence completed. Use a held chord or remove the shorter binding. Held actions use a single key/chord, not a tap sequence.

Move actions select a face, direction, and outer/slice/wide turn. **Follow solve depth controls** inherits the current depth and direction controls. Explicit bindings can use a fixed direction or follow/opposite the direction toggle. The selected depth and held action keys transform the resolved move. Slice takes precedence over wide when both are held; reverse flips the result.

Available non-turn actions include next-move depth, held slice/wide/reverse, held or persistent mode selection, mode cycling, undo, redo, scramble, home/fit view, reset to solved, clearing pending input, and resetting TPS. Reset to solved retains its confirmation when a solve would be discarded.

## Modes

Modes are independent tables. For example, CIF can bind F to `U′`, while EIF binds F to `R`. Put a Cycle keyboard modes action on M in both modes to switch between them. Alternatively, assign Space to Hold keyboard mode → EIF in CIF; release Space to restore CIF. A held mode may itself provide other held-mode bindings. Larger mode chords suppress smaller held actions that form part of that chord, and releasing them restores those actions.

Duplicate creates an editable copy; Add empty creates a blank table. A blank mode has no implicit reserved move bindings. Use the Active mode selector to return to another mode if you have not bound a mode-switch key yet. Deleting a mode also removes bindings that target it.

Changing modes or pressing suffix/action keys does not execute a turn. The selected persistent mode saves; temporary held modes, pressed keys, pending depths/sequences, and live statistics do not survive reloads.

## TPS

TPS uses a trailing 1-, 3-, or 5-second window. A counter and peak accompany it. Each accepted manual turn counts once, regardless of width/depth. Keyboard turns, sticker drags, and face-button turns count. Depth/suffix keys, held actions, mode changes, unmapped keys, auto-repeat, undo/redo, and automatic scramble moves do not count. The meter measures accepted turn input, not animation completion. A full input queue rejects additional moves and does not count them.

Use Reset input stats or a configured Reset TPS action to clear the session counter and peak. Keyboard bindings still operate with the overlay hidden.

## Persistence and portability

Configuration is stored in `master-fto-keyboard-v1` in local storage, separate from solves and other display preferences. Export keyboard downloads a versioned JSON file. Import validates the whole configuration before replacing it; invalid imports retain the existing configuration. Keep an export when sharing or transferring a setup between browsers.

The format supports up to 40 modes, 400 bindings per mode, six tap-sequence steps, five keys in a chord, and move depths 1–20. Identical actions may appear on many different triggers. These limits do not alter the puzzle's size or exact turn geometry.
