# Keyboard and recording overlay

Enable **Show keyboard** in Settings. The overlay uses physical key positions rather than the characters generated by the operating system. Keycaps display their current actions: for example, the F position can display `U′`, `8Fw`, or `8F`. Keys without an action stay empty. ANSI and ISO layouts include the function row, navigation cluster, inverted-T arrows, staggered letter rows, and correctly sized modifiers/Space/Enter. The optional number pad has tall Enter/Add and a double-width zero. The 60% layout shows only the 61-key main block; hidden function/navigation/numpad keys never light another keycap.

The keyboard is anchored at the bottom of the column to the right of the square puzzle. The saved solve-time list scrolls above it without covering it. When that space is too narrow, the panel moves below the square. Its default maximum width is 900px, with a 220–1200px width setting; its actual size fits the available panel. Peak and turn count are available in the TPS tooltip.

The overlay is interactive as well: pointer presses on keycaps use the same input engine as physical keys. Press highlights follow key-down and key-up directly, without a minimum duration, afterglow, fade, or polling delay. A 10ms press is not intentionally stretched; visible timing is still limited by browser rendering and display refresh. Pending suffix selection and its faint affected-key glow are separate indicators, not held-key highlights. Move labels are frozen for that press, so consuming a suffix does not relabel a lit key as a different turn.

## Defaults by puzzle size

Each size has independent bindings and modes. The recording overlay preferences are shared. The 3×3 has CIF, EIF-R, EIF-L, and E Center; other sizes start with just the 16 outer moves, number suffixes, and undo/redo/home/cancel commands. Every binding remains editable.

| Physical keys | CIF moves |
| --- | --- |
| F / J | U′ / U |
| G / H | F′ / F |
| E / D | L′ / L |
| I / K | R / R′ |
| R / U | B′ / B |
| S / W | BL / BL′ |
| L / O | BR′ / BR |
| A / ; | D / D′ |

Numbers 2–9 select that width; 0 selects 10, and 1 selects 11. Shift+1–9 select 11–19; Shift+0 selects 20. Shift+8 (`*`) or NumpadMultiply selects 18. Out-of-range suffixes are blank and inactive. A full-size width is labeled **Cube rotation** and changes the view without changing the puzzle, timer, history, or TPS. A dedicated **Cube rotation (face axis)** action can be bound separately.

On 3×3, Space also selects width two, Shift holds a single-slice action, Y/B are Rw/Rw′ and T/V are Lw′/Lw. Ctrl-wide, Alt-reverse, and the one-shot slice suffix are unbound by default. Add **Next move: slice suffix** to any key to avoid holding Shift. Slice and width suffixes stack in either order: with Quote bound to slice, `8 ' F` performs `8U′` on a sufficiently large puzzle. Both suffixes are consumed by one accepted turn; unmapped keys and mode changes do not consume them. Press a suffix again or Escape to cancel it.

Tab switches CIF ↔ EIF-R; C switches CIF ↔ EIF-L. EIF-R cycles F → R → BR → B → BL → L → F, including wide moves; EIF-L cycles in the opposite direction. U and D are unchanged. M switches CIF ↔ E Center. E Center has F/H = U′/U, K/D = R/R′, S/L = Rw′/Rw, and E/I = 2R′/2R. These are binding tables; changing a mode does not rotate the view.

Ctrl/Meta+Z or Backspace undo player moves, stopping at the generated scramble. Ctrl/Meta+Shift+Z or Ctrl+Y redo; Home restores the view; Escape clears pending input. Mouse and face-button modifiers retain Shift-wide/Ctrl-slice/Ctrl+Shift-ultra behavior.

## Editing bindings

Open **Settings → Keyboard & bindings**. Select **Mode to edit**, then choose an existing binding or New binding. Enter a trigger, or use Record chord and press/release the chord together. Choose an action and save. Clicking an existing trigger edits that row; adding a duplicate is rejected rather than overwriting it.

- `F`: a single physical key.
- `A+F`: hold A and press F. Chord order does not affect conflict detection.
- `Ctrl+Alt+F`: a modifier chord.
- `A F`: tap A, then F within the sequence timeout.
- `KeyF`, `ShiftLeft`, `ShiftRight`, `ArrowUp`, `Numpad8`, `IntlBackslash`: explicit physical codes.
- `Ctrl`, `Control`, `Shift`, `Alt`, and `Meta` match either side. Side-specific bindings are supported; overlapping generic/side-specific duplicates are rejected.

The timeout is configurable. An immediate action cannot also be the start of a longer tap sequence: it would execute before the sequence completed. Use a held chord or remove the shorter binding. Held actions use a single key/chord, not a tap sequence.

Move actions select a face, direction, and outer/slice/wide turn. **Follow solve depth controls** inherits the current depth and direction controls. Explicit bindings can use a fixed direction or follow/opposite the direction toggle. The selected depth and held action keys transform the resolved move. Slice takes precedence over wide when both are held; reverse flips the result.

Available non-turn actions include cube rotation, one-shot slice, next-move depth, held slice/wide/reverse, held or persistent mode selection, mode cycling, undo, redo, scramble, home/fit view, reset to solved, clearing pending input, and resetting TPS. Reset to solved retains its confirmation when a solve would be discarded.

## Modes

Mode keys show their target mode names; unbound shortcut-prefix keys stay blank. Names contain one or two words, each at most six characters, separated by one space. Existing longer names are shortened while retaining their bindings and mode IDs.

Modes are independent tables. For example, CIF can bind F to `U′`, while EIF binds F to `R`. Put a Cycle keyboard modes action on M in both modes to switch between them. Alternatively, assign Space to Hold keyboard mode → EIF in CIF; release Space to restore CIF. A held mode may itself provide other held-mode bindings. Larger mode chords suppress smaller held actions that form part of that chord, and releasing them restores those actions.

Duplicate creates an editable copy; Add empty creates a blank table. A blank mode has no implicit reserved move bindings. Use the Active mode selector to return to another mode if you have not bound a mode-switch key yet. Deleting a mode also removes bindings that target it.

Changing modes or pressing suffix/action keys does not execute a turn. The selected persistent mode saves; temporary held modes, pressed keys, pending depths/sequences, and live statistics do not survive reloads.

## TPS

TPS uses a trailing 1-, 3-, or 5-second window. A counter and peak accompany it. Each accepted manual turn counts once, regardless of width/depth. Keyboard turns, sticker drags, and face-button turns count. Cube rotations, depth/suffix keys, held actions, mode changes, unmapped keys, auto-repeat, undo/redo, and automatic scramble moves do not count. The meter measures accepted turn input, not animation completion. A full input queue rejects additional moves and does not count them.

Use Reset input stats or a configured Reset TPS action to clear the session counter and peak. Keyboard bindings still operate with the overlay hidden.

## Persistence and portability

Size-specific profiles are stored in `master-fto-keyboard-v2` in local storage, separate from solves. Untouched old defaults upgrade automatically; customized legacy keyboards migrate to the active size. Export keyboard downloads the current size’s configuration as versioned JSON. Import validates the whole configuration before replacing the current size’s bindings; invalid imports retain the existing configuration. Keep an export when sharing or transferring a setup between browsers.

The format supports up to 40 modes, 400 bindings per mode, six tap-sequence steps, five keys in a chord, and move depths 1–20. Identical actions may appear on many different triggers. These limits do not alter the puzzle's size or exact turn geometry.
